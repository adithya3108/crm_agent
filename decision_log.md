# Decision Log

1. **Brand: XboxSupport.** Chosen over SpotifyCares (too much DM-handoff, resolutions happen off-platform) and AmericanAir (broader/higher-stakes intents, also DM-heavy for account issues). XboxSupport has substantive in-thread answers and a bounded intent space.
2. **Thread reconstruction** uses `in_response_to_tweet_id` to pair each XboxSupport reply with the customer tweet it answers, plus up to 3 turns of prior context walked backward through the reply chain (23,235 threads reconstructed).
3. **Intent taxonomy derived from data**, not imported from Banking77 (not a good fit; Banking77 is finance-specific). Built by manually reading an 80-message random sample and grouping into 10 categories.
4. **Split billing_subscription and purchase_store into separate intents** even though both involve payment, because failure modes and correct actions differ (unwanted charge/refund vs. failed transaction at point of sale).
5. **Added a noise_other intent** for thanks/praise/venting/unparseable messages (roughly 15-20% of sample). These should mostly auto-close rather than escalate, so they need their own bucket rather than being forced into a "real" category.
6. **Reply drafting uses TF-IDF retrieval over historical (customer, reply) pairs**, not embeddings, chosen for speed and zero extra API cost given the 15-min reproduction constraint. Known limitation: TF-IDF misses semantic near-duplicates that use different wording, likely contributing to the ~3.5/5 groundedness ceiling.
7. **Golden set (200 examples) was AI-drafted then reviewed by the author**, not purely hand-labeled from scratch. Documented explicitly because the assignment requires "hand-labeled by you"; flagged as a methodology limitation (see "what's misleading" in report) since the same model family labels and predicts, likely inflating intent accuracy vs. fully independent human labels.
8. **Escalation logic went through 3 iterations** (see report Results section) after v1 conflated "reply asks for a DM" with "vague/unresolved." Since DM-handoff is XboxSupport's *normal* successful resolution pattern on this brand, that conflation caused massive over-escalation (recall 94.6%, precision 32.1%). v2 fixed precision but crashed recall (43.2%) by narrowing escalation triggers too far to just 2 intent categories plus explicit anger. v3 re-added "no concrete next step" and "repeated/unresolved issue" as escalate triggers, which raised recall back to 56.8% but dropped precision to 42.9%, netting a roughly flat F1 (50.8% to 48.8%). No version dominates on both precision and recall; a 4th iteration would need a structured multi-factor rubric rather than another single free-text prompt tweak.
9. **Two baselines chosen deliberately**: trivial (majority-class intent plus always-auto-handle) exposes that escalation "accuracy" is a misleading metric on an imbalanced set (163 auto / 37 escalate); simple keyword-rule baseline shows the LLM classifier's real lift isn't just from picking common words.
10. **LLM-as-judge scores 3 dimensions (grounded/helpful/tone) rather than one overall score.** Kept them separate because tone consistently scores much higher (~4.4) than grounded/helpful (~3.5), and collapsing to one number would hide that gap, which is itself a useful finding.
11. **A v3 eval run failed on a transient DNS/network error partway through, but the failure was not immediately obvious**: the previously-written `eval_report.json` from v2 was still on disk and looked like a completed, plausible v3 result. Caught only by diffing per-example escalation decisions between the "v3" file and the actual v2 file (found 0 differences, which was the tell). The real v3 run was then re-executed and verified the same way (23/200 decisions differed from v2, confirming the second run was genuine). Documented because it's a concrete case of "the number looked fine but wasn't the number I thought it was," directly relevant to the report's own "what's misleading" section.
12. **Human-vs-judge agreement measured with a blind scoring artifact**, not by showing the author the judge's scores first. This matters: seeing the judge's number first would anchor the human's own score toward it, defeating the point of an independent check. Found a systematic bias (human scores ~0.5-0.9 points higher than judge, on a 1-5 scale) and weak correlation (0.35 or less); documented in report section 2 and factored into the "misleading" section, since the ~3.5/5 judge quality scores reported throughout understate how a human actually perceives these replies.
